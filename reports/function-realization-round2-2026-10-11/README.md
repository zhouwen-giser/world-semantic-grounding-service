# 第二轮功能做实：复合历史分析与真实 PostgreSQL 验证

本轮完成当前 WSGS 契约内的复合高级历史分析。验证范围为本地生产调用链、受控 Gateway HTTP 夹具和隔离 PostgreSQL；现场 SACS、模型、GOWM/GSAP 业务数据及重新部署均为 **NOT_RUN**。

## 已实现

- 明确分隔的道路、事件、指标排名请求可组合，最多八项；每项保留自身目标、FIRST/LAST、指标及结果。相同子句去重，不同主体、任务、执行批次或数据来源明确拒绝。
- 同一请求只查询一次轨迹并进行一次主体准入。共用总期限和节点、行数、候选、输出与执行时间预算；CROSS 按两节点计算。预算不足在历史查询前拒绝。
- 道路与 CROSS 的相同地图匹配输入复用本请求内已验证的完整结果和回执。复用不跨请求；失败不缓存，仍检查引用有效期、可用性和期限。
- 每项独立返回结果或类型化失败。道路 Provider 返回 503 时，排名仍可返回；轨迹投影等待阻止全部依赖项并保留等待原因。
- 公开结果沿用 1.2 契约。复合 Gap 的原因格式为 `ANALYSIS_<序号>_<类型>[_<事件>]/<原因>`；源证据、引用闭包、租约及 Finding/Choice 哈希继续验证。
- 后续选择只绑定对应分析的证据，支持非首项排名和独立事件目标。同类事件的 A/B 目标分别校验，主体与目标不能互相覆盖。动作候选仍需当前状态验证、路线规划和执行确认。
- 每项固定配方有独立且稳定的查询 ID；普通执行及仅编译均持久化实际计划。仅编译不会隐式查询轨迹、目标或 Provider；部分计划成功时返回 PARTIAL，并列出其他各项缺少的目标。
- 增加 `npm run test:postgres`：编译当前工作区后，以已有 PostgreSQL 17 镜像建立本机一次性容器、回环端口、内存数据目录及两个独立数据库，串行执行四套集成测试并清理。拒绝远程 Docker，不使用现有数据库 URL 或主机数据卷。

## 尚需上游扩展：自由时间窗

当前锁定的 `historical-trajectory-query` 和 `task-execution-interval-query` 均设置 `additionalProperties=false`，没有时间窗过滤字段。因此继续返回 `HISTORICAL_TIME_WINDOW_UNSUPPORTED`，不在本地裁剪后冒充同一个 GOWM 轨迹引用。

可行的最小上游方案：

1. GOWM 在新版本轨迹查询契约中加入可选的绝对时间范围，使用明确的 UTC 起止与 `[)` 边界；与执行批次、阶段和来源约束在服务端求交集。
2. GOWM 为实际查询范围提供一致的轨迹引用、版本、requested/defined/excluded periods、完整度及等待状态。范围外为空与投影尚未就绪必须区分，不重建任务事实或设备状态。
3. GSAP 沿该引用消费同一范围；WSGS 经受控契约接入、锁与摘要更新后，将时间约束下传并验证返回范围、引用和版本。先支持绝对时间；相对日期需先有权威时区语义。
4. 验收覆盖范围外样本不可见、暂停排除、跨缺口不推断事件、等待原因、租约与版本失效，以及道路/事件/排名对同一范围的组合分析。

这些契约改动不在本轮 WSGS 代码中伪造实现。本轮没有重新生成部署包、更新远程服务器或修改共享业务数据。
